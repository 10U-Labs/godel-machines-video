# Machines That Rewrite Themselves

Narration script, draft 8. One paragraph is one voiced line. Lines starting
with ">" are notes and are not voiced.

The film explains recursive self-improvement and three machines built on it:
the Gödel Machine improves itself, the Darwin Gödel Machine improves itself
through its children, and the Huxley-Gödel Machine improves itself through its
families. Each scene carries one idea. Pip, the program that follows the story,
is made up. Each scene follows from the one before it with a "but" or a
"therefore". The joins:

> 00 Pip fixes programs, BUT one day the program to fix is Pip's own code.
> 01 A program is text, THEREFORE Pip can open its own file and change it.
> 02 THEREFORE each better Pip makes a better change: recursive self-improvement.
> 03 THEREFORE a design: one machine that rewrites itself, the Gödel Machine.
> 04 BUT it was never built. THEREFORE, once programs could write code, a team built one that improves through its children.
> 05 THEREFORE it got better, generation after generation.
> 06 BUT a parent's own score says little about its descendants.
> 07 THEREFORE the next machine improves through families: clades.
> 08 THEREFORE three machines, three ways to improve.

## 00-pip | A program that fixes programs

This is Pip. Pip is a computer program, and its job is to fix other programs.

Give Pip a program with a mistake in it, and Pip finds the mistake, and fixes it.

Pip is made up. But programs like Pip are real, and this video is about them.

[pause 0.8]

One day, Pip is given a new program to fix. It is Pip's own code.

## 01-a-program-is-text | A program is text

To see how that can work, start with what a program is.

A program is a piece of text. It is a list of instructions, kept in a file.

Pip reads files like that all day. Its own instructions are just one more file.

So Pip can open that file, and change it.

## 02-better-at-getting-better | Better at getting better

Say Pip finds a way to fix programs a little better, and writes it into its own code.

Now Pip is better at fixing programs, and that includes its own code.

So its next change can be a better one. And the change after that, better still.

Each round makes Pip better at the job of making Pip better.

This is called recursive self-improvement. Recursive means that something is done to its own result, again and again.

## 03-godel-machine | Improving itself

In 2003, a computer scientist named Jürgen Schmidhuber described a machine that does exactly this. He called it the Gödel Machine.

A Gödel Machine is one program that improves itself. While it does its job, it rewrites its own code to do the job better.

It can change any part of itself. Even the part that makes the changes.

If Pip were a Gödel Machine, there would only ever be one Pip, changing itself again and again.

## 04-darwin-godel-machine | Improving through children

The Gödel Machine was never built. But in 2025, a team of researchers built a machine that grows from the same idea. They called it the Darwin Gödel Machine.

It does not change itself in place. Instead, a program like Pip writes a changed copy of its own code. The copy is a new program: its child.

The child is tested on real programming problems, and gets a score. Then a parent is picked, it has a child, and it happens again.

Programs with higher scores are picked as parents more often. So the programs get better, one generation after another.

And the old ones are never thrown away. Any of them can become a parent again later.

## 05-it-got-better | It got better

In the team's run, the first program solved 20 problems in a hundred.

After 80 rounds, its best descendant solved 50.

## 06-the-wrong-parents | The wrong parents

But each parent is picked by its own score.

Later that year, a second group found that a program's own score says little about how good its children and grandchildren will become.

## 07-huxley-godel-machine | Improving through families

So their machine looks at whole families instead.

A program, together with its children, their children, and so on down, is called a clade. This machine is called the Huxley-Gödel Machine.

Each program is rated by how well its whole clade does. The programs whose families do best are picked to have more children.

So the question is not which Pip is best. It is which Pip starts the best family.

The Huxley-Gödel Machine reached a higher score than the Darwin Gödel Machine, and used less than half the computer time.

## 08-three-machines | Three machines

So, three machines, and three ways for a program to improve itself.

The Gödel Machine improves itself: one program, rewriting its own code.

The Darwin Gödel Machine improves itself through its children: each new version is the child of an old one.

The Huxley-Gödel Machine improves itself through its families: it grows the branches whose descendants do best.

[pause 0.6]

Today, programs rewrite their own code, and the new versions are better at it than the old ones were.

How far that goes, nobody knows yet.
